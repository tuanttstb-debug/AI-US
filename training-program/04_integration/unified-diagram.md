# Sơ đồ hợp nhất — 3 trụ là một vòng, không phải 3 khóa

> Một hình để cả team nhớ: Design Thinking chọn đúng việc → Agile giao đúng cách → Growth khiến mỗi vòng giỏi hơn.

```
        KIM CƯƠNG 1              KIM CƯƠNG 2                VÒNG LẶP
      (đúng vấn đề)            (đúng giải pháp)            (giao & học)

   Discover ─ Define    │   Develop ─ Deliver    │   Plan → Build → Review → Retro
   Empathize  Define    │   Ideate   Test        │        ▲                  │
      \       /         │    \       /           │        └──────────────────┘
       \     /          │     \     /            │      giao tăng dần, học từng vòng
        \   /           │      \   /             │
    ═══ DESIGN THINKING ═══│═════ (bàn giao) ════│════════ AGILE ═══════════════

   ╚══════════════════════ GROWTH (mindset nền) ══════════════════════╝
        Goal · Reality · Options · Will · Track · Harvest
        Học từ mỗi test (DT) và mỗi retro (Agile) → vòng sau tốt hơn
```

## Ngôn ngữ chung — cùng một tư duy, ba tên gọi

| Growth (nền) | Design Thinking | Agile |
|---|---|---|
| **Goal** — outcome, không phải task | Point of View / HMW | Sprint Goal / Product Goal |
| **Reality** — tách fact/assumption | Empathize / Define (pain thật) | Acceptance Criteria (đo được) |
| **Options** — nhiều phương án | Ideate | Prioritization (MoSCoW) |
| **Will** — hành động trong quyền | chọn ý tưởng để prototype | commit story trong Decision Rights |
| **Track** — đo kết quả thật | Test prototype | Review / demo |
| **Harvest** — rút learning + standardize | Test learning | Retrospective |

## Vòng khép kín
```
   Design Thinking ──▶ Agile ──▶ (khách hàng dùng)
        ▲                              │
        │                              ▼
        └────────── Growth ◀── học từ thực tế
             (learning → khám phá lại đúng hơn)
```

Phản hồi từ người dùng thật (sau khi giao) → GROWTH LOG → quay lại Discover cho vòng sau. Đó là lý do 3 trụ **không rời rạc**: chúng nối đuôi nhau thành một vòng cải tiến liên tục.

## Câu mang về
> **Mỗi vòng đi qua team phải để lại: một hiểu biết đúng hơn về vấn đề (DT), một cách giao gọn hơn (Agile), và một learning được ghi lại (Growth).**
